## Root `package.json`

```jsonc
{
  "workspaces": ["packages/*", "apps/*"],
  "packageManager": "npm@10.9.7",
  "scripts": {
    "dev": "turbo run dev --filter @hridayanp/docs --filter @hridayanp/storybook",
    "build": "turbo run build",
    "typecheck": "turbo run typecheck"
  }
}
```

The `workspaces` field instructs npm to hoist third-party dependencies to the
root and to symlink the twelve packages into `node_modules/@hridayanp/`. That
symlink is why `raster-layer` importing `@hridayanp/geo-utils` resolves to the
working copy rather than to a registry artefact.

> **Warning:** `packageManager` is **required** by Turborepo 2.10, which reads
> the field to determine which package-manager binary to invoke. Removing it
> causes every task to fail with `Could not resolve workspace`. Turborepo also
> rejects a `devEngines.packageManager` range spanning more than one major
> version, which is why the pinned legacy field is used.

## `turbo.json`

```jsonc
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "inputs": [
        "src/**", "stories/**", ".storybook/**", "scripts/**",
        "index.html", "tsup.config.ts", "vite.config.ts",
        "tsconfig.json", "package.json"
      ],
      "outputs": ["dist/**", "storybook-static/**"]
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "inputs": ["src/**", "stories/**", ".storybook/**",
                 "vite.config.ts", "tsconfig.json", "package.json"]
    },
    "dev":   { "cache": false, "persistent": true },
    "clean": { "cache": false }
  }
}
```

`^build` declares that a task depends on the same task in its dependencies.
Turborepo derives the order from each package's `dependencies` field, so
`geo-utils` → `raster-utils` → `raster-layer` is resolved automatically and no
ordering list is maintained.

`inputs` and `outputs` govern content-addressed caching. A task whose declared
inputs are unchanged replays from cache in tens of milliseconds and reports
`FULL TURBO`. The input globs must cover every file that affects output: the
apps keep stories in `stories/`, Storybook configuration in `.storybook/`, and
build scripts in `scripts/`, none of which fall under `src/**`.

`typecheck` depends on `^build` because each package is checked against its
dependencies' **emitted declarations** rather than their source. This verifies
that the published type surface is coherent — a property that source-to-source
checking does not establish.

## `tsconfig.base.json`

Extended by every package. The settings that materially affect output:

```jsonc
{
  "strict": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "noImplicitOverride": true,
  "isolatedModules": true,
  "verbatimModuleSyntax": true,
  "declaration": true,
  "moduleResolution": "Bundler"
}
```

`verbatimModuleSyntax` requires `import type` for type-only imports, which
prevents tsup from emitting runtime imports for bindings that are erased at
compile time. `isolatedModules` guarantees that every file can be transpiled
independently — a precondition for esbuild, which tsup uses.

## Package layout

Every package follows the same structure:

```text
packages/raster-layer/
├── package.json      name, exports map, peers, scripts
├── tsconfig.json     extends the base configuration
├── tsup.config.ts    entry point, output formats, externals
├── README.md         published to npm alongside the code
└── src/
    ├── index.ts      the sole public surface
    ├── RasterLayer.tsx
    ├── useRasterImage.ts
    ├── cache.ts
    └── types.ts
```

`src/index.ts` defines the entire public API. The `exports` map in
`package.json` seals every other path, so no consumer can depend on an internal
module and subsequently break on an internal refactor.

## `apps/docs`

This site: a Vite and React application with a History-API router, markdown
content rendered through `marked`, and a live map on the landing page that
imports the packages through the workspace.

```text
apps/docs/
├── src/
│   ├── site.ts          page registry — drives sidebar, router, search, navigation
│   ├── content.ts       glob-imports the markdown and builds the search index
│   ├── markdown.ts      marked configuration: heading anchors, highlighting, callouts
│   ├── router.tsx       pushState router
│   ├── components/
│   └── content/*.md     the pages in this section
└── scripts/embed-storybook.mjs
```

The build runs `vite build` and then copies `apps/storybook/storybook-static`
into `dist/storybook`, producing a single deployable directory that serves the
documentation at `/` and Storybook at `/storybook` from one origin — no reverse
proxy and no cross-origin configuration.

## `apps/storybook`

Storybook 9 on the Vite builder.

Its `.storybook/main.ts` aliases `@hridayanp/*` to package **source** rather
than to `dist`. Stories therefore reflect a source edit immediately, and
`npm run dev` requires no prior build. The alias pattern is anchored
(`^@hridayanp/ui$`) so that `@hridayanp/ui/styles.css` is not captured by it; a
prefix match would rewrite the stylesheet request into a path inside
`index.ts`.

## `smoke.mjs` and `smoke-docs.mjs`

Two headless-browser verification scripts. `smoke.mjs` serves the built
Storybook and loads 22 story identifiers; `smoke-docs.mjs` serves the built docs
site and loads the landing page plus every registered documentation route. Both
fail on any uncaught exception, page error or React warning.

They exist because static type checking establishes that the code compiles — not
that a MapLibre map initialises, that deck.gl acquires a WebGL2 context, or that
a layer attaches without throwing. See
[Testing & Verification](/docs/verification).
