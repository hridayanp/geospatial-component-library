## Root `package.json`

```jsonc
{
  "workspaces": ["packages/*", "apps/*"],
  "packageManager": "npm@10.9.7",
  "scripts": {
    "dev": "turbo run dev --filter @hridayanp/docs --filter @hridayanp/storybook",
    "build": "turbo run build",
    "typecheck": "turbo run typecheck"
  }
}
```

`workspaces` is what makes npm hoist third-party dependencies to the root and
symlink the twelve packages into `node_modules/@hridayanp/`. That symlink is why
`raster-layer` importing `@hridayanp/geo-utils` resolves to your working copy
rather than a registry download.

> **Warning:** `packageManager` is **required** by Turbo 2.10 — it reads the
> field to decide which binary to invoke. Remove it and every task fails with
> `Could not resolve workspace`. Turbo also rejects a `devEngines.packageManager`
> range that spans more than one major, which is why this is the pinned legacy
> field.

## `turbo.json`

```jsonc
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "inputs": ["src/**", "tsup.config.ts", "tsconfig.json", "package.json"],
      "outputs": ["dist/**", "storybook-static/**"]
    },
    "typecheck": { "dependsOn": ["^build"], "inputs": ["src/**", "tsconfig.json"] },
    "dev":       { "cache": false, "persistent": true },
    "clean":     { "cache": false }
  }
}
```

`^build` means "build my dependencies first". Turbo derives the order from each
package's `dependencies` field, so `geo-utils` → `raster-utils` → `raster-layer`
is automatic and there is no order list to maintain.

`inputs` and `outputs` drive the cache. Edit a README and Turbo replays the
cached build in about 50 ms (`>>> FULL TURBO`). Edit `src/` and it rebuilds only
that package and its dependents.

`typecheck` depends on `^build` because each package typechecks against its
dependencies' **emitted `.d.ts`**, not their source. That is deliberate — it
verifies the published type surface is coherent, which typechecking against
source would not.

## `tsconfig.base.json`

Shared by every package. The settings that matter:

```jsonc
{
  "strict": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "noImplicitOverride": true,
  "isolatedModules": true,
  "verbatimModuleSyntax": true,
  "declaration": true,
  "moduleResolution": "Bundler"
}
```

`verbatimModuleSyntax` forces `import type` for type-only imports, which keeps
tsup from emitting runtime imports for things that vanish at compile time.
`isolatedModules` guarantees every file can be transpiled independently — a
requirement for esbuild, which tsup uses.

## Inside a package

Every one of the twelve looks the same:

```text
packages/raster-layer/
├── package.json      name, exports map, peers, scripts
├── tsconfig.json     extends the base, sets rootDir/outDir
├── tsup.config.ts    entry, formats, externals
├── README.md         published to npm alongside the code
└── src/
    ├── index.ts      the ONLY public surface
    ├── RasterLayer.tsx
    ├── useRasterImage.ts
    ├── cache.ts
    └── types.ts
```

`src/index.ts` is the entire public API. The `exports` map in `package.json`
seals everything else, so no consumer can reach into `dist/internal/whatever`
and then break when you refactor.

## `apps/docs`

This site. A Vite + React SPA with a ~50 line History-API router, markdown
content rendered by `marked`, and a live demo on the landing page that imports
the real packages through the workspace.

```text
apps/docs/
├── src/
│   ├── site.ts          page registry — drives sidebar, router, search
│   ├── content.ts       glob-imports the markdown, builds the search index
│   ├── markdown.ts      marked config: heading anchors, highlighting, callouts
│   ├── router.tsx       pushState router
│   ├── components/
│   └── content/*.md     every page you are reading
└── scripts/embed-storybook.mjs
```

The build runs `vite build` and then copies `apps/storybook/storybook-static`
into `dist/storybook`, so a single deploy serves the docs at `/` and Storybook
at `/storybook` from one origin — no proxy, no CORS.

## `apps/storybook`

Storybook 9 on the Vite builder, with 22 story files.

Its `.storybook/main.ts` aliases `@hridayanp/*` to package **source**, not
`dist`. Stories therefore hot-reload on a source edit, and `npm run dev` needs
no prior build. The alias regex is anchored (`^@hridayanp/ui$`) so that
`@hridayanp/ui/styles.css` is not swallowed by it — a prefix match would rewrite
it into a path inside `index.ts`.

## `smoke.mjs`

Serves the built Storybook, loads 22 story ids in headless Chromium, and fails
on any uncaught error, page error or React warning.

It exists because a typecheck proves the code compiles — not that a MapLibre map
initialises, that deck.gl gets a WebGL context, or that a layer attaches without
throwing. See [Testing & Verification](/docs/verification).
